Project Overview

High-Level Summary

The PERWER system is a comprehensive solution for monitoring, predicting, and managing battery, solar, and grid operations. It consists of a robust backend for data processing and AI predictions, and an intuitive frontend for visualization and user interaction. The product is designed to provide real-time insights, predictive analytics, and actionable logs for operational efficiency and maintenance planning.

Purpose of the Software

  • Enable real-time monitoring of battery, grid, solar, and generator status
  • Provide AI-driven predictions for battery health and operational metrics
  • Centralize logs and events for operational transparency and troubleshooting
  • Empower users with a dashboard for actionable insights and historical data review

System Architecture

High-Level Architecture

The PERWER system follows a client-server architecture, where the frontend (client) communicates with the backend (server) via RESTful APIs. The backend is responsible for data aggregation, log/event processing, and AI predictions, while the frontend provides real-time visualization and user interaction.

+-------------------+ REST API +-------------------+
| Frontend (JS) | <--------------------> | Backend (Flask) |
| Dashboard, Logs | | Data, AI, Logs |
+-------------------+ +-------------------+
  • Frontend requests data, logs, and predictions from backend APIs
  • Backend processes requests, runs AI models, and returns JSON responses
  • No direct database connection from frontend; all data flows through backend APIs

APIs and Data Flow

  • Data flows from backend to frontend as JSON payloads (e.g., SOC, SOH, grid status)
  • Frontend triggers API calls for dashboard updates, log retrieval, and AI predictions
  • Backend endpoints handle requests, process data, and respond with structured results

Real-Time Communication

  • The current system uses periodic polling from frontend to backend for real-time updates
  • WebSockets are not implemented yet
  • Future improvements may include WebSocket support for push-based real-time delivery

  • Supabase Integration: Handles data upload/retrieval from Supabase

Data Handling

Example Payload Sent to Frontend

{ "SOC": 78.5, "SOH": 95.2, "pv_power_w": 3200, "grid_status": "ON", "generator_status": "OFF", "battery_voltage": 52.3, "timestamp": "2025-08-28T14:32:00Z" }

Field Descriptions

  • SOC: State of Charge (%), rule-based calculation
  • SOH: State of Health (%), rule-based calculation
  • pv_power_w: Solar panel power output (watts)
  • grid_status: Grid connection status (ON/OFF)
  • generator_status: Generator status (ON/OFF)
  • battery_voltage: Current battery voltage (V)
  • timestamp: ISO 8601 formatted record time

Log Generation

Logs are created on key events:

  • Grid ON/OFF
  • Generator ON/OFF
  • Battery charge/discharge events
  • Solar activity

Each log entry includes:

  • Event type (e.g., grid ON)
  • Timestamp
  • Relevant metrics (SOC, SOH, etc.)

Logs are stored in Supabase and retrievable via /logs endpoint (supports filtering by event type or time range).

AI Predictions

  • SOC and SOH are computed using rule-based thresholds in prediction.py
  • Backend process:
    1. Parse incoming metrics
    2. Apply rule-based logic
    3. Return SOC and SOH predictions as JSON
  • Predictions are displayed in the frontend's AI Panel and updated in real-time

Usage Guide

  • Users access via the frontend web dashboard
  • No authentication required (unless implemented in future)

Dashboard Overview

Displays real-time metrics for:

  • Battery
  • Grid
  • Solar
  • Generator

Key values (SOC, SOH, pv_power_w, grid_status, etc.) update dynamically.

Viewing Logs

  • The Log Window shows chronological system events

  • Logs: Historical list of operational events with timestamps
  • AI Predictions: Up-to-date SOC and SOH with clear indicators

Example User Flow

  1. User opens dashboard and sees live metrics
  2. User checks logs to verify system operation
  3. User views AI predictions for battery health
  4. User interacts with the system via the frontend
